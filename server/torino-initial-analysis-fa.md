# گزارش تحلیل اولیه پروژه تورینو
## فاز اول: ارزیابی، نیازسنجی و تحلیل اولیه

## ۱. پکیج‌ها و ابزارهای مورد استفاده

- **React Hook Form:** برای مدیریت فرم ورود با کد یک‌بارمصرف و فرم ویرایش پروفایل؛ کمک می‌کند فرم‌ها ساده‌تر مدیریت شوند.
- **TypeScript:** برای مشخص کردن نوع داده‌ها و کاهش خطاهای زمان توسعه.
- **Tailwind CSS:** برای پیاده‌سازی سریع و یکدست طراحی فیگما و هماهنگ کردن ظاهر صفحات در اندازه‌های مختلف صفحه.
- **Zod:** برای اعتبارسنجی ورودی فرم‌ها، مانند کد ورود و اطلاعات پروفایل.
- **React Icons:** برای استفاده از آیکون‌ها در بخش‌های مختلف رابط کاربری.
- **React Context:** برای نگهداری وضعیت‌های مشترک مورد نیاز، مانند وضعیت ورود کاربر یا اطلاعاتی که چند بخش از برنامه به آن‌ها نیاز دارند. در شروع پروژه از Context استفاده می‌کنم و فقط اگر پیچیدگی وضعیت‌ها بیشتر شود، ابزار دیگری را بررسی می‌کنم.
- **Next.js:** برای ساخت صفحات و مدیریت مسیرهای پروژه.

## ۲. مدیریت وضعیت سراسری (Global State)

برای این پروژه از **React Context** استفاده می‌کنم، چون در حال حاضر نیازی به اضافه کردن کتابخانه جداگانه‌ای برای مدیریت وضعیت نمی‌بینم.

مواردی که ممکن است به وضعیت مشترک نیاز داشته باشند:
- وضعیت ورود کاربر
- اطلاعات عمومی کاربر که در چند بخش نمایش داده می‌شود
- اطلاعات سبد خرید، در صورتی که لازم باشد در بخش‌هایی مثل هدر و صفحه سبد خرید هم‌زمان نمایش داده شود

اطلاعاتی که از بک‌اند دریافت می‌شوند، در صورت نیاز می‌توانند در همان صفحه یا بخش مربوط به خودشان مدیریت شوند. بهتر است همه داده‌ها بدون نیاز واقعی وارد Context نشوند تا ساختار برنامه ساده بماند.

## ۳. صفحات و روش رندرینگ

بر اساس قابلیت‌های مشخص‌شده در بک‌اند، صفحات اصلی پروژه شامل موارد زیر خواهند بود. تعداد نهایی صفحات پس از بررسی فیگما مشخص می‌شود.

- **صفحه اصلی و فهرست تورها**
  - روش رندرینگ: ISR یا SSR
  - دلیل: اطلاعات تورها باید به‌روز باشد و انتخاب نهایی به نحوه تغییر اطلاعات در بک‌اند بستگی دارد.

- **صفحه جزئیات تور**
  - روش رندرینگ: SSR یا ISR
  - دلیل: اطلاعات هر تور از بک‌اند دریافت می‌شود و باید با اطلاعات واقعی همان تور هماهنگ باشد.

- **صفحه ورود**
  - روش رندرینگ: CSR برای بخش تعاملی فرم
  - دلیل: ارسال و بررسی کد یک‌بارمصرف به تعامل کاربر وابسته است.

- **صفحه سبد خرید**
  - روش رندرینگ: CSR
  - دلیل: محتوای سبد خرید به کاربر واردشده وابسته است و ممکن است در طول استفاده تغییر کند.

- **صفحه پروفایل**
  - روش رندرینگ: CSR
  - دلیل: اطلاعات شخصی کاربر دریافت و از طریق فرم ویرایش می‌شود.

- **صفحه تورهای کاربر**
  - روش رندرینگ: CSR
  - دلیل: اطلاعات به حساب کاربر وابسته است.

- **صفحه تراکنش‌ها**
  - روش رندرینگ: CSR
  - دلیل: اطلاعات تراکنش‌ها خصوصی و وابسته به کاربر است.

- **صفحه ثبت سفارش یا تکمیل خرید**
  - روش رندرینگ: CSR
  - دلیل: ثبت سفارش در نتیجه اقدام مستقیم کاربر انجام می‌شود.

## ۴. ساختار پروژه

ساختار پروژه را بر اساس Next.js App Router تنظیم می‌کنم تا صفحات، کامپوننت‌های مشترک و کدهای مربوط به هر قابلیت از هم جدا باشند.

│   │   │   └── tours/

دلایل انتخاب این ساختار:
- پوشه `app` برای صفحات و مسیرهای پروژه است.
- گروه‌های `(public)`، `(auth)` و `(user)` صفحات را دسته‌بندی می‌کنند، بدون این‌که نام گروه در آدرس صفحه نمایش داده شود.
- پوشه `components` برای اجزایی است که در چند صفحه استفاده می‌شوند.
- پوشه `context` وضعیت‌های مشترک برنامه را نگه می‌دارد.
- پوشه `lib` برای کدهای مربوط به ارتباط با بک‌اند است.
- پوشه‌های `types` و `utils` به‌ترتیب برای نوع‌های TypeScript و توابع کمکی هستند.
- فایل `.env.example` نام متغیرهای محیطی مورد نیاز را مشخص می‌کند؛ اطلاعات محرمانه را در مخزن کد قرار نمی‌دهم.

## ۵. بخش‌های چالش‌برانگیز پروژه

- **ورود با کد یک‌بارمصرف:** مدیریت ارسال کد، بررسی آن، نمایش خطا و کنترل وضعیت ورود کاربر.
- **مدیریت سبد خرید:** هماهنگ نگه داشتن اطلاعات سبد خرید با بک‌اند و نمایش تغییرات آن در رابط کاربری.
- **ثبت سفارش:** مدیریت ارسال درخواست، نمایش نتیجه و جلوگیری از ارسال ناخواسته چندباره.
- **صفحات مخصوص کاربر:** نمایش اطلاعات پروفایل، تورها و تراکنش‌های مربوط به کاربر واردشده.
- **دریافت اطلاعات تورها:** مدیریت حالت‌های بارگذاری، خطا و نبود اطلاعات.
- **پیاده‌سازی واکنش‌گرا:** هماهنگ کردن صفحات با طراحی فیگما در موبایل و دسکتاپ.

## ۶. الگوهای تکرارشونده در UI

پس از بررسی طرح فیگما، اجزای تکراری را به کامپوننت‌های قابل استفاده مجدد تبدیل می‌کنم. مواردی که باید بررسی شوند:

- هدر و فوتر
- کارت تور
- دکمه‌ها
- فیلدهای ورودی و فرم‌ها
- آیکون‌ها
- پیام‌های خطا و موفقیت
- حالت‌های بارگذاری
- پنجره‌های تأیید یا مودال‌ها
- عنوان و چیدمان مشترک صفحات
- بخش‌های مشترک پنل کاربر

## ۷. جمع‌بندی

بر اساس قابلیت‌های پروژه، تورینو به صفحاتی برای نمایش و مشاهده جزئیات تورها، ورود کاربر، سبد خرید، ثبت سفارش و مدیریت اطلاعات حساب کاربری نیاز دارد.

برای پیاده‌سازی از Next.js، TypeScript، Tailwind CSS، React Hook Form، Zod و React Icons استفاده می‌کنم. برای مدیریت وضعیت مشترک نیز در ابتدا React Context را انتخاب می‌کنم تا ساختار پروژه ساده بماند.

ساختار پوشه‌ها را به‌گونه‌ای تنظیم می‌کنم که صفحات، کامپوننت‌های مشترک و منطق ارتباط با بک‌اند از هم جدا باشند. روش رندرینگ و تعداد نهایی صفحات را با توجه به نیاز هر صفحه و طراحی فیگما نهایی می‌کنم.
